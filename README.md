# Letter Receipt System

A production-oriented Spring Boot + MySQL web application for recording physical letter deliveries and receptionist confirmation.

## Workflow

1. Delivery person selects an existing profile or enters a new profile.
2. They select/create the sending organization, choose the configured recipient, and enter letter details.
3. The server records the delivery time and generates a tracking number.
4. Reception sees the item under **Pending Receipts**, verifies the physical letter, and confirms receipt.
5. The server records the authenticated receptionist and receipt time. The public tracking page shows the delivery status.

## Stack

- Java 21
- Spring Boot 3.5.16
- Spring MVC + Thymeleaf
- Spring Security / BCrypt
- Spring Data JPA / Hibernate
- MySQL 8.4
- Flyway database migrations
- Spring Boot Actuator health endpoint
- Docker + Docker Compose

## Quick start with Docker

```bash
cp .env.example .env
# IMPORTANT: edit .env and replace every example password

docker compose up -d --build
```

Open `http://localhost:8081`.

Admin login uses `ADMIN_USERNAME` / `ADMIN_PASSWORD` from `.env`. `.env` is the source of truth for this account: on every startup, if the stored password differs from `ADMIN_PASSWORD`, it is updated to match (a reset made on the Admin page for this account is overwritten at the next restart, so change `.env` instead). The React dev server (`letter-delivery system frontend`, `npm run dev`) reads the same `.env` and adds these credentials to reception/admin API calls, so after changing the password just restart the backend. If the database has no users and the bootstrap password is missing or shorter than 12 characters, the application refuses to start.

### First-time configuration

1. Log in as Admin at `/login`.
2. Open **Administration**.
3. Add the people who can receive letters under **Recipients**.
4. Optionally preload common external organizations.
5. Create receptionist user accounts.
6. Use the public kiosk page `/` for deliveries and `/reception` for receipt confirmation.

## Run without Docker

Requirements: Java 21, Maven 3.6.3+, MySQL 8.x.

Create the database/user, then export:

```bash
export DB_HOST=localhost
export DB_PORT=3306
export DB_NAME=letter_receipt
export DB_USER=letter_app
export DB_PASSWORD='...'
export APP_BOOTSTRAP_ADMIN_USERNAME=admin
export APP_BOOTSTRAP_ADMIN_PASSWORD='use-a-long-random-password'
export APP_BOOTSTRAP_ADMIN_DISPLAY_NAME='System Administrator'
export APP_ORGANIZATION_NAME='Your Organization'
export APP_TIMEZONE='Africa/Accra'

mvn clean test
mvn spring-boot:run
```

Integration tests use Testcontainers (Docker must be running) and cover create → receive → track plus MockMvc security checks. They are skipped automatically if Docker is not available. `mvn test` also writes a JaCoCo report to `target/site/jacoco`.

## Production deployment notes

- Terminate TLS/HTTPS at Nginx, Apache, a cloud load balancer, or another trusted reverse proxy.
- Keep MySQL private; do not expose port 3306 publicly.
- Store secrets in your platform secret manager rather than committing `.env`.
- Set `APP_TIMEZONE` to the office timezone. Delivery/receipt timestamps are generated by the server.
- Back up the MySQL database regularly and test restores.
- `/actuator/health` is intentionally public for health checks; other actuator endpoints are not exposed.
- Change or disable staff accounts promptly when responsibilities change.
- Serve the app over HTTPS and set `SPRING_PROFILES_ACTIVE=prod` so session cookies are `Secure` and MySQL connections require TLS.
- Login and public delivery POSTs are rate-limited per client IP. Increase `APP_RATE_LIMIT_PUBLIC_POST` if a busy shared kiosk is throttled.

## API

### Public

- `GET /api/public/recipients`
- `GET /api/public/organizations`
- `GET /api/public/delivery-persons?q=...`
- `POST /api/public/deliveries`
- `GET /api/public/deliveries/{trackingNumber}`

### Reception API (HTTP Basic: RECEPTIONIST or ADMIN)

- `GET /api/reception/deliveries/pending`
- `POST /api/reception/deliveries/{id}/receive`

### Admin API (HTTP Basic: ADMIN)

- `GET/POST /api/admin/recipients`
- `PUT /api/admin/recipients/{id}`
- `GET/POST /api/admin/organizations`
- `PUT /api/admin/organizations/{id}`

The HTML application uses the same service layer as the API.

## Data integrity / security decisions

- Delivery and receipt times are created by the backend, never trusted from the browser.
- Receipt confirmation records the authenticated user.
- A delivery history table provides an immutable workflow audit trail.
- Tracking numbers are random tokens assigned in the same insert as the letter, not sequential IDs.
- Optimistic locking protects a letter record from conflicting updates.
- Passwords are BCrypt-hashed.
- Database schema is managed by Flyway; Hibernate runs in validation mode.
- Public status lookup deliberately returns a reduced data set.
